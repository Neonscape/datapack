# 源文件命令的失败边界

行改名、公共/本地校验规则定义改名与删除、新建公共 Schema，先捕获所有会改写的文件，再执行写入，刷新成功后才发布 Undo/Redo 历史与工作区。调用方明确传入的目标也必须进入快照，不能只依赖上一次项目树（磁盘可能新增了文件）。

失败补偿保留普通文件的原始字节及 Go 可恢复的权限位（Perm、setuid、setgid、sticky），内容和权限没变时不重复写入或 chmod。缺失文件与零字节文件不同，读取错误会阻止命令；可读或悬空 symlink、非普通文件都不能当作普通源文件原子替换，相关源命令在写入前拒绝。新建失败只清理本次创建的空目录，非空目录不会递归删除。

如果回写或最终 rename 也失败，错误会包含恢复副本的具体路径，保留原始字节供人工恢复；恢复文件没有 `.cue` 扩展，不进入项目扫描。失败不发布新历史，原有历史双栈及工作区状态保留。不要把“报告失败”误读为已自动恢复全部文件，应检查聚合错误中的补偿失败。

这些保证属于进程内历史和已报告 I/O 失败的补偿。没有承诺崩溃恢复、多文件对外原子可见、防外部并发修改、inode/硬链接身份、owner/group、ACL 或 xattr 恢复。普通文件原子替换的继承边界仍是内容与上述 mode；后续若要支持额外文件系统元数据，应先建立明确协议与平台回归。
