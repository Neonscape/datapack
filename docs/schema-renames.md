# Schema 定义改名的边界

定义的内部名与显示名是不同概念。改名只迁移被选中的 CUE 定义、它的注册信息和显示名元数据；行、列、表身份及导出的数据值不变。修改显示名无需修改引用。

引用在改声明前按 CUE 词法绑定识别。同名的公共定义、另一张表的 `_local` 定义、嵌套作用域的定义与普通字段标签都保持原样。公共引用同时匹配本地模块导出路径、package qualifier 与 import alias；同目录同 package 的其他文件可以引用该声明。仅当项目中该 package 唯一时兼容旧的无 import package 选择器。

改名后重新绑定裸引用，若新名字会被嵌套定义捕获则拒绝。多文件重复声明/目标冲突、无 import 的同名 package 歧义、经组合或下标等无法可靠确定来源的 package 派生访问也拒绝；拒绝发生在任何源文件提交前。这里只支持项目提供的受限 CUE 文档，不宣称对所有任意 CUE 程序提供语义重构。

没有变化的文件保留原始字节，不顺手格式化或删 import。发生变化的候选先做结构与编辑模型校验，再走现有多文件替换与 workspace 成功刷新后记历史的协议。正常 Undo/Redo 包括所有受影响的源与标题；I/O 补偿、权限与恢复副本的边界见 `source-transactions.md`。这不是崩溃恢复或外部并发事务。

注意：CUE 本身支持 import alias；当前应用的 Schema 索引仍按 package ID 识别部分引用，带别名的表达式可能产生“Schema reference ... does not exist”诊断。改名能够按真实 import 改写，并不代表该索引兼容性缺口已经解决。
