# 云岚纪：中文 RPG 配表实战

这是一个原创单机队伍 RPG 的配表工程：青岚村的星脉失衡，旅人沿赤砂遗迹寻找线索，最后在霜月城修复星井。三章各有八个关卡、八种敌人和十六个任务。人物和地点均为本样例虚构。

从本目录的 `yunlan-rpg.dtproj` 打开。它与原有 skyharbor 独立，16张表、1002行数据；480行是中英本地化，522行是玩法数据。实际字段名、枚举、备注和说明均用中文，只有稳定ID、目录、package和逻辑表名保留ASCII。没有额外设置同名显示标题，所以不会出现“标价（标价）”双表头。

先读这篇导览，再用 [功能索引](FEATURES.md) 找字段。编辑实验请先“文件→另存为”创建自己的副本；下文预期值指原始样例。手动编译模式下要先点“编译”，再观察公式预览与诊断。

## 五分钟：改价并导出

1. 在工程树打开 `economy.product`（商品），定位 `product_01_1`。它是青岚村药铺出售的第一阶行旅药剂，`标价=40`、`折扣=0.8`，`实售价` 的公式是 `ceil(标价 * 折扣)`，因此显示32。
2. 将 `标价` 改100，重新编译，`实售价` 应变80。这里向上取整是为避免金币出现小数；不是跨表读取道具价格。道具表和商品表的定价由策划分别维护。
3. 右键 `标价` 单元格可以查看或编辑中文评论。表头直接显示真实字段名。
4. 在工程设置确认 `system.parameter` 未选中；在表导出设置确认 `策划备注` 未选中。执行CSV导出，应得到 `exports/` 下15个文件；商品CSV含 `标价,折扣,实售价`，不含 `策划备注`；不生成系统参数CSV。
5. Undo恢复40，Redo恢复100。原文中公式仍在 `_tool.formulas`，不会把80写成行内固定值。

## 第一条阅读链：文本、英雄、技能、效果、道具

打开 `localization.text` 的 `hero_01_name`，`简体中文=陆青禾`，`英语=Lu Qinghe`。`名称文本ID` 是普通标量外键；编辑器不会自动把ID联表替换成译文，游戏运行时需要选择语言列。

接着打开 `content.hero` 的 `hero_01`：

- `名称文本ID` 引向上面的文本；`简介文本ID` 给出角色背景。
- `技能ID` 是四个ID的数组，第一项 `skill_01`。它是一个完整单元格，双击打开数组编辑器；不是四列，也不是结构体数组。
- `skill_01.主效果ID=effect_01`，在 `content.effect` 中查看其类别“伤害”、强度10、持续1回合。技能倍率与效果强度在游戏运行时组合，表中不声称有跨表公式。
- 四种定位各有明确招式：战士破阵斩是伤害、游侠疾矢射是伤害/缚足箭是控制、医师回春术是治疗、术士引星术是伤害。每人的第三项是开战触发一次的被动，法力和冷却都为0。英雄技能ID列出完整四槽招式，解锁等级由游戏运行时判断，并非初始全部可用；该等级是英雄学习门槛，敌人按遭遇表直接装配既有招式。敌人技能也按其遭遇身份选择主动招式；例如弓手用疾矢射、祭司用回春术、首领用陨星。
- `初始装备ID=item_weapon_01` 指向 `content.item`。武器、防具、饰品都是道具类别，分别用 `装备槽位=主手/躯干/饰品` 区分；这样背包、合成和商店可以共享一套道具ID。
- `出生坐标={横:0,纵:0}` 使用英雄表本地 `#坐标`，双击可编辑两个中文结构成员。它是扁平结构，没有嵌套数组。

F12或按住Ctrl/Command点击引用单元格可查看导航目标；数组使用数组编辑器/引用菜单，不要把整个JSON字符串当成一个目标ID。中文实际列名与Schema名参与编辑、公式、导航和导出，ASCII ID负责稳定关系。

## 第二条阅读链：任务、关卡、敌人、掉落、工坊

`quest_01` 是青岚村溪桥的讨伐任务，`关卡ID=stage_01`、`需求数量=3`；`quest_02` 要收集两份 `item_material_01`。查看下列具体关系：

1. `world.stage.stage_01.敌人ID=["enemy_01"]`，后续关卡是 `stage_02`。最后一关 `stage_24` 的后续关卡明确为null。
2. `world.enemy.enemy_01.掉落组ID=loot_01`，其明细为 `drop_01_1` 至 `drop_01_3`：两种材料及一种药剂，权重0.4/0.3/0.3，合计1。样例约定每组抽一次；这个跨行合计规则由附带回归验证，工具没有通用跨表规则引擎。
3. `craft.recipe.recipe_01` 产出 `item_weapon_01`，解锁任务为 `quest_02`。两条材料关系是 `ingredient_01_1`、`ingredient_01_2`，分别有独立的材料ID和数量。
4. 关卡奖励和任务奖励继续指向道具。任务的 `奖励道具ID` 约定列表中每个ID发一件；没有另一个脆弱的平行数量数组。
5. `economy.shop.shop_01` 是默认开放的药铺，其他商店通过任务解锁。`economy.product` 每行是一种商品，限购数量与价格在同一行。

每个地区有四阶材料与装备、八处遭遇；差异体现在解锁条件、等级、强度、配方和价格，不是重复上千条无关行。

每个收集任务的指定关卡至少有一种敌人能掉落目标材料，任务目标文字写出具体材料名。掉落是有概率的，可能需要重复挑战；敌人ID列表表示种类，不规定一次生成数量。收集目标按背包拥有数量检查，不额外消耗；实际合成才按材料关系扣除。此处是样例的游戏运行约定，编辑器不代替游戏执行任务或战斗。

## 数值、Schema与真实公式

公共Schema在 `schema/common.cue`：`#资源标识`、`#必填文本`、`#稀有度`等是type；`#非负`、`#正数`、`#概率范围`是constraint。`#概率`把number与 `#概率范围` 组合；列也可以用 `int & common.#非负` 组合requirements。这里的requirements是类型/约束引用，不是任务解锁条件。

本地Schema：英雄和关卡各自有 `#坐标` type，成长表有 `#等级` constraint，商品表有 `#折扣范围` constraint。本地定义只属于本表，公共定义可以被多个表导入。定义名称使用中文，package仍为 `common`。

- `balance.growth.level_01.参考战力`：`基础攻击 * 3 + 基础防御 * 2 + floor(基础生命 / 10)`，原值 `23*3+12*2+floor(225/10)=115`。
- `level_01.累计经验=0`；`level_02.累计经验` 明确读取同表 `level_01` 的累计经验和升级经验，结果103。后续60级形成无环链；等级ID稳定，不受界面位置影响。
- 公式允许同行和同表完整地址引用，不能通过外键读取另一张表。也不能读取数组元素、切片或动态下标。
- 道具 `item_potion_01` 省略 `可交易`，按Schema默认true。它的 `效果ID` 用专门的行内默认表达式 `*"effect_04" | string` 选择“回春”，演示非字面量来源的默认外键；其他药剂有明确治疗效果。材料和任务物品的 `效果ID` 明确为null，列本身没有Schema默认值，因此它们真正无效果。注意：若列有Schema默认值，本工具按既有规则将省略值或null交给默认值处理，不能靠写null绕过默认值。本例取消了原先全列默认护心的牵强设置。数组用 `[]` 表达空列表，null、空字符串和空数组不是一个值；完整规则见 [Schema格式](../../restricted-cue-schema-v1.md)。
- 原始 `system.parameter.level_cap=60` 与成长上限一致。参数表是设计参考，不参与跨表公式；产品已有Schema只验证其非负，完整业务一致性由本样例回归补充。

## 在副本中练习编辑与安全保护

- 先在商品表选 `product_01_1` 的 `标价`，向下粘贴两行：第一行100，第二行200。第一行实售价80，第二行折扣1、实售价200；Undo一次撤销整个粘贴。
- 重命名商品中文列 `标价→售价`，同行公式、导出列和相关评论会迁移；Undo/Redo后检查值不变。不要只改显示名来模拟改字段。
- 在公共Schema编辑器将 `必填文本→非空文字`，检查文本表、系统参数等引用同步；Undo恢复。仍被使用的定义不允许直接删除。
- 重命名 `item_weapon_01` 为 `item_qinglan_blade`，英雄、配方、商品的字面量外键会更新。删除这把仍被引用的武器应被拒绝。
- 尝试重命名 `effect_04`：`item_potion_01` 有行内默认表达式产生的非字面量引用，因此当前安全策略是拒绝改名并保持文件和历史不变。不要手工只改目标ID。
- 新行ID使用ASCII，如 `item_trial_blade`；新行值仍按CUE单元格语法输入，字符串加双引号，数组/结构使用专用编辑器。已有普通字符串列编辑输入文字即可；以 `=` 开头表示公式。
- 删除带附件的独立测试表前，先确认运行版本包含附件恢复修复PR #10；进程内Undo/Redo可以恢复附件，但历史不提供崩溃恢复。不要把Undo当备份。

当前没有行排序、筛选、全文搜索和自动联表显示；设计文档将这些列为后续功能。行按稳定ID排序，可以沿ID和引用导航；项目导出表选择、表级导出列选择是现有功能，不能冒称行筛选。

## 只在副本里排查故障

把 `effect_07.触发概率` 改1.2，应出现范围诊断；把技能的 `主效果ID` 改成不存在的ID，应出现可定位的外键诊断。点诊断后，网格和公式栏应指向同一个中文字段。Undo恢复后重新编译。

把未导出的 `system.parameter.level_cap.数值` 改-1：即使该表不输出CSV，整个工程也必须拒绝导出，已有有效CSV保持不变。Undo后导出应恢复成功。不要在教学原件里保留这些故障。
