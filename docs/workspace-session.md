# 前端会话与异步读取

`useWorkspaceSession` 负责项目 view、标签、活动标签、Schema peek 的一致状态转换。文件路径是文档身份，显示名不参与身份。打开/关闭/改名使相关读取失效；较早的慢打开可以成为后台标签，但不能抢走后来选择的焦点。

会话同时使用项目 generation、后端 projectEpoch/source revision 和同类请求序号。同一路径重新打开也产生新的 generation/epoch。迟到响应不能越过项目切换；有权威版本的表和工作区不能覆盖更新 revision。安全单元格 delta 还必须匹配原表 revision、行 ID/位置和列身份；无法匹配时读取权威完整表，不把乐观输入当作提交成功。

持久化 RPC 在 bridge 的写队列中按顺序派发。Undo/Redo 可能在一个普通编辑尚未响应时入队，因此不能仅因前一个编辑发布了 view 就丢弃后续已经提交的 history 结果。项目/请求仍有效且后端 epoch/revision 更新的结果可以接纳；旧工程、较旧 revision 和同类旧请求仍拒绝。错误按项目和请求归属呈现，不因队列前面的正常发布而静默丢失。

Undo/Redo 在 App 共用一个 single-flight，从派发前开始，到成功结果及必要完整文档已由 React 提交后才释放。同步 ref 拦住同一事件循环里的重复快捷键；菜单同时禁用两种历史操作。完成状态使用新对象，即使立即失败导致 pending true/false 被批处理，也会在 layout commit 后解锁。重复触发不分配新的 history 序号，因而后一个失败不能淘汰已经提交的前一个成功。错误路径也通过同一提交边界释放，仍可正常重试；工程切换不放行旧结果。

刷新保留本地 Schema 草稿及无版本旧协议的标签实例身份。带权威版本的表读取可以替换较旧的同工程表，即使该表实例来自队列前面的编辑；不得覆盖更高 revision。关闭的标签不因刷新重新打开；只有新项目树确认路径消失时才关闭现存标签。读取失败保留原标签，不能误当作删除。规则 peek 根据稳定定义 ID 与最新选择协调。

成功导出发布后端返回的 validation workspace。公式表或版本变化的表读取新 DTO；同 revision 的无公式表保留原值并清除已失效的旧诊断，避免为普通 100k 字面量表重传全部行。整个导出与必要刷新期间保留前端重操作锁，不重复调用 Compile。

`sessionState` 提供纯辅助转换，`tabRead` 负责只读文档。真实 App 组合回归覆盖延迟编辑后 Undo/Redo、delta 与完整读取、旧工程响应及导出 freshness；mock IPC 不能替代持久化或原生桌面验收。对应 Go 和原生证据另列在性能研究报告。
