# 前端会话与异步读取

`useWorkspaceSession` 负责项目 view、标签、活动标签、Schema peek 的同一次状态转换。App 调用打开、关闭、迁移文档和应用定义结果等命令，不再拿到 tabs/active 的 React setter；项目初始化只有一个会话入口。文件路径仍是数据身份，显示名不参与身份。

打开文件和 Undo/Redo 的异步读取带有项目 generation 与同类请求序号。同一项目重新打开也产生新 generation。迟到响应不能越过项目切换；同一标签重复打开只接纳最新读取；关闭标签会使其先前的读取失效。较早的慢打开可成为后台标签，但不会抢走后来选择的焦点。

刷新开始时只记录当时的标签实例，读取完成后与当前实例比较。用户期间新开/关闭/重开/更新的标签保持当前状态；没有变化的实例才接纳读取结果。读取失败保留原标签和文档；只有新的项目树确认源路径已消失时才关闭它。旧数据会保留到下次成功读取，不把读取失败误当成删除。

`sessionState` 包含状态类型和纯辅助转换；`tabRead` 的 reader 契约只读文档并构造候选，不依赖 Wails 或 React。会话层拥有顺序/身份检查及最终应用，Wails 调用由 App 注入。metadata-only refresh 仍保留 Schema 新定义/选择/内部草稿的原有规则，语义变更仍按已有规则协调。

此批覆盖 open/history，不宣称所有编辑命令都已经有请求协议。其他持久化命令、原生文件对话框的并发语义、同一路径的外部并发写入需要单独验证；不取消或回滚用户已经要求的后端写入。真实浏览器验证使用 mock IPC，Go 测试覆盖持久化语义，不能替代原生桌面交互。
